# Karaoke Reader

공개 URL: [Karaoke Reader](https://aaidensong.github.io/karaoke-reader/)

영어 대본의 현재 문장을 화면에 고정하고 WPM에 맞춰 단어를 채우는 읽기·말하기 연습 도구입니다.

## 현재 범위

단어 채움 재생, 미국식 IPA 사전, PWA, 대본 라이브러리·검색·공유 링크와 모바일 터치 조작을 제공합니다. 프레임워크와 번들러를 사용하지 않습니다.

- `index.html`: 문서 구조와 화면
- `assets/app.css`: 기존 스타일과 운영체제 설정에 따른 라이트·다크 테마
- `assets/app.js`: 재생, 문장 분할, 파일 불러오기, 단축키, 발음 표시
- `assets/i18n.ko.js`: 한국어 UI 문구
- `assets/script-format.js`: 앱과 검사 도구가 함께 쓰는 대본 형식 파서
- `library/index.json`, `library/<category>/<id>.md`: 분야별로 구성한 대본과 생성 목록
- `tools/build-library.mjs`, `tools/lint-library.mjs`: 목록 생성과 대본 검사
- `sw.js`: 앱 파일과 발음 사전의 오프라인 응답, 앱 버전 갱신
- `manifest.webmanifest`, `assets/icons/`: 설치 정보, PNG 아이콘과 SVG 원본

## 로컬 실행

저장소 루트에서 Python 3으로 실행합니다.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 엽니다. 별도 빌드는 필요하지 않습니다.

재생 버튼 또는 Space로 재생·일시정지하고, 대본 편집에서 텍스트를 입력하거나 `.txt`, `.md`, `.srt`, `.vtt`, `.docx`를 불러옵니다. `?` 버튼에서 단축키를 확인할 수 있습니다. 대본과 설정은 이 브라우저의 localStorage에 저장됩니다.

## 사용법과 단축키

첫 방문에는 라이브러리가 열립니다. 분야·수준·유형·검색으로 대본을 고른 뒤 재생합니다. 라이브러리를 닫으면 예시 글이 재생 대기 상태로 남습니다. 두 번째 방문부터는 마지막으로 저장한 대본(저장한 대본이 없으면 예시 글)으로 시작합니다. `#script=<id>` 공유 링크는 해당 대본으로 바로 시작합니다. 저장 공간을 지우면 첫 방문 상태로 돌아갑니다.

화면 아래에서 재생·문장 이동·발음기호·대본 편집·설정을 조작합니다. 문장 영역을 눌러도 재생·일시정지가 됩니다. WPM은 분당 단어 수이며, 낮은 속도에서 읽고 익숙해지면 올립니다. 글자 크기와 문장 간격은 넓은 화면의 하단 바에서 조절합니다.

| 키 | 동작 |
|---|---|
| Space | 재생·일시정지 |
| ← / → | 이전·다음 문장 |
| R | 현재 문장 처음부터 |
| Shift+R | 대본 처음부터 |
| ↑ / ↓ | WPM 10 증가·감소 |
| P | 발음기호 켜기·끄기 |
| − / = (숫자패드 − / + 포함) | 글자 크기 축소·확대 |
| F | 전체 화면 |
| E | 대본 편집 |
| / 또는 ? | 단축키 도움말 |
| Esc | 편집·도움말·대화상자 닫기 |

단축키는 한글 자판에서도 같은 물리 키로 동작합니다. 입력 중이거나 설정·라이브러리가 열려 있으면 재생 단축키가 작동하지 않습니다. 직접 입력·불러온 파일은 서버로 보내지 않으며 브라우저 저장 공간을 지우거나 다른 기기에서 열면 복원되지 않습니다.

## 발음 사전 빌드

Node.js와 npm이 설치된 환경에서 저장소 루트에서 실행합니다. 검증 환경은 Node.js v26.13.0, npm 11.20.0입니다.

```sh
npm ci
npm run build:ipa
```

`cmu-pronouncing-dictionary` 3.0.0을 개발 의존성으로 고정하고, 대체 발음 항목(`(숫자)` 접미사)을 제외한 126,046개 단어를 `data/ipa-en-us.json`에 생성합니다. 음절 구분 점과 강세 표시는 제공된 변환 로직을 그대로 사용합니다.

- `regression`: `rə.ˈɡrɛ.ʃən`
- `minute`: `ˈmɪ.nət`

생성 파일을 저장소에 포함하므로 앱을 로컬 서버로 실행할 때 빌드할 필요는 없습니다. 빌드 시 네트워크 접근은 npm 의존성 설치에만 필요합니다. 사전 라이선스는 `NOTICE.md`에 기록했습니다.

## 발음 사전 사용

1. 발음기호 버튼 또는 P를 누릅니다. 페이지 안 설정 창에 다운로드 안내가 표시되며, 이때까지 사전을 요청하지 않습니다.
2. 다운로드를 누르면 `data/ipa-en-us.json`을 받습니다. 비압축 응답은 진행률과 수신 KB를 표시하고, 전체 크기를 모르면 수신 KB만 표시합니다. `Content-Encoding`이 있는 압축 응답은 숫자 없이 진행 중임을 표시합니다.
3. 다운로드가 끝나면 발음기호가 켜집니다. 실패하면 같은 창의 **다시 시도**를 누릅니다. 다운로드 취소나 Esc로 중단할 수 있습니다.
4. 받은 사전은 내용 검증 후 서비스 워커와 공유하는 브라우저 캐시에 저장합니다. 발음기호를 껐다 켜거나 새로고침해도 사전을 다시 요청하지 않습니다. 켬·끔 설정은 localStorage에 저장해 복원합니다. 캐시가 없으면 기억된 설정이 켬이어도 꺼진 상태로 시작하며 자동 다운로드하지 않습니다.
5. **설정 → 발음 사전 삭제**를 누르면 메모리와 브라우저 캐시의 사전, 화면의 발음기호를 지우고 꺼짐을 저장합니다. 새로고침 후 다시 켤 때 다운로드 확인을 받습니다. 삭제에 실패하면 재시도를 안내합니다.
6. 저장 공간 부족이나 브라우저 제한으로 캐시에 저장하지 못하면 페이지 안에 안내합니다. 이때는 현재 페이지에서만 사용할 수 있습니다. 브라우저가 저장 공간을 비우면 다음 사용 시 다운로드 확인을 다시 받습니다.

공개 GitHub Pages 응답을 2026-11-06에 측정했습니다. `Content-Encoding: gzip`이며 응답 본문 전송량은 880,931바이트(약 0.88MB), 압축 해제 후 JSON은 3,338,113바이트(약 3.34MB)입니다. 따라서 안내의 “약 0.9MB”를 유지합니다. HTTP 헤더 등 통신 부가 비용은 제외한 값이며, 압축하지 않는 로컬 서버에서는 약 3.34MB를 전송합니다. 서버·브라우저의 압축 협상에 따라 전송량이 달라질 수 있습니다.

## 설치와 오프라인 사용

서비스 워커는 HTTPS 또는 localhost/127.0.0.1에서 동작합니다. HTML 파일을 직접 열거나 일반 HTTP 주소로 접속하면 오프라인 설치를 사용할 수 없습니다. 로컬 서버의 `/`와 GitHub Pages 형태의 `/karaoke-reader/` 하위 경로를 모두 지원합니다.

온라인에서 앱을 한 번 열어 서비스 워커 설치가 끝나면, 비행기 모드에서도 같은 주소를 열거나 새로고침해 대본 편집과 재생을 할 수 있습니다. 발음기호는 사전을 미리 받아 둔 경우 사용할 수 있습니다. 지원 브라우저의 설치 메뉴 또는 홈 화면에 추가로 설치할 수 있으며 설치와 가입은 필수가 아닙니다.

앱 파일은 버전별로 함께 저장하고, 새 버전 설치가 성공하면 이전 앱 캐시를 지웁니다. 사전 캐시는 앱 버전과 분리해 유지합니다. 배포 후 새로고침 한 번으로 새 서비스 워커를 확인하고, 활성화되면 페이지를 한 번 자동으로 다시 열어 새 앱을 적용합니다. 설치가 실패하면 이전 버전을 유지합니다.

앱 파일을 바꾸면 `npm run stamp:sw`를 실행하고 커밋합니다. `tools/stamp-sw.mjs`가 `sw.js`의 `APP_FILES`에 나열된 파일 내용과 경로, 버전 값을 제외한 서비스 워커 내용을 SHA-256으로 계산해 `APP_VERSION`에 기록합니다. 파일 목록은 `sw.js` 한 곳에서 관리하며, 도구가 읽을 수 있도록 JSON 형식의 문자열 배열로 유지합니다. `./`는 `index.html` 내용으로 계산합니다. 버전 값을 손으로 올릴 필요는 없습니다.

```sh
npm run stamp:sw
npm run check:sw
```

`check:sw`는 현재 내용과 기록된 버전이 다르면 종료 코드 1로 실패하며 `sw.js`를 수정하지 않습니다. 앱 파일과 갱신된 서비스 워커를 같은 커밋·배포에 포함해야 합니다. GitHub Actions도 `npm run check:sw`를 실행해 누락을 검사합니다.

사전은 설치 목록에 포함하지 않으며, 앱 업데이트로 자동 다운로드하지 않습니다. 사전 요청의 `cache: 'no-store'`는 HTTP 캐시에서 삭제된 사전이 복원되는 일을 막습니다. 별도의 Cache API 저장·조회에는 영향을 주지 않으므로 유지했습니다.

## 라이브러리와 대본 추가

**라이브러리** 버튼을 누르면 분야별 목록이 열립니다. 실생활의 다양한 상황에 맞춘 대본을 수준·유형으로 고르거나 제목·상황으로 검색할 수 있습니다. 대본을 선택하면 재생 화면으로 이동하며 권장 WPM을 자동 적용합니다. 재생 버튼으로 연습을 시작합니다.

대화의 상대 대사는 본문과 같은 글꼴을 쓰며 기울임과 색으로 구분합니다. 단어를 채우지 않으며 표시 시간은 단어 수와 WPM을 기준으로 합니다. **내 대사만 연습**을 켜면 상대 문장을 1초만 표시합니다. `※` 안내문은 재생하지 않습니다. 질문·답변 대본은 질문을 제목으로 표시합니다.

라이브러리에서 연 대본은 **공유 링크 복사**로 `#script=<id>` 주소를 복사할 수 있습니다. 복사가 제한된 환경에서는 선택된 링크를 직접 복사합니다. 공유 링크는 라이브러리 대본의 id만 담으며 개인 편집 내용이나 파일은 업로드하지 않습니다. 직접 불러온 형식 대본도 같은 표시 규칙과 권장 WPM을 적용하지만 공유 버튼은 표시하지 않습니다.

대본 작성 규칙은 [library/AGENTS.md](library/AGENTS.md), 파일 형식은 [SCRIPT_FORMAT.md](SCRIPT_FORMAT.md)를 확인합니다. 파일 추가·수정 뒤 다음 명령을 실행하고 대본과 생성 목록을 함께 커밋합니다.

```sh
npm run lint:library
npm run build:library
```

검사는 분야·수준·유형별 집계와 오류·경고를 출력합니다. 고의 위반 예시는 `npm run lint:library -- tools/fixtures`로 확인하며 종료 코드 1이 정상입니다. 특정 파일이나 폴더를 인자로 넘길 수도 있습니다.

GitHub Actions는 push와 PR마다 lint, build, 커밋된 `library/index.json`과 재생성 결과의 비교, `check:sw`를 실행합니다. 생성 목록은 본문 해시도 담으므로 대본 본문만 수정한 경우에도 다시 빌드해야 합니다.

앱은 목록만 먼저 받고 본문은 선택할 때 받습니다. 대본 본문과 목록은 앱 셸 캐시에 넣지 않습니다. 이미 열었던 라이브러리 대본을 오프라인에서 다시 선택하는 기능은 이번 범위에 포함하지 않습니다. 현재 편집기의 대본 텍스트는 기존대로 localStorage에 저장합니다.

## GitHub Pages 배포

저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, **main**, **/ (root)**로 배포합니다. 공개 주소는 이 문서 첫 부분에 있습니다. main에 변경을 병합하면 GitHub Pages가 다시 배포하며, **Actions → pages build and deployment**에서 결과를 확인합니다. 루트의 `.nojekyll`은 기본 Jekyll 변환을 막아 front matter가 있는 대본 `.md`를 원본 경로로 제공합니다. 이 파일을 삭제하면 대본 본문 요청이 404가 될 수 있습니다. 별도 빌드 서버나 앱 빌드는 필요하지 않습니다.

배포 전 `npm run lint:library`, `npm run build:library`, `npm run check:sw`를 통과시키고 생성 목록을 함께 커밋합니다. 앱 파일을 바꿨으면 검사 전에 `npm run stamp:sw`를 실행합니다. 배포 후 공개 주소에서 라이브러리·공유 링크·발음기호를 확인하고, 사전을 받은 브라우저를 오프라인으로 바꿔 새로고침합니다. 기존 탭에서 새로고침 한 번 후 새 버전의 서비스 워커 캐시로 교체되는지도 확인합니다.

## 현재 제약

기존 Google Fonts 요청과 `.docx`를 처음 불러올 때 사용하는 Mammoth CDN 요청은 유지했습니다. 외부 리소스는 앱 캐시 대상에 포함하지 않습니다. 오프라인에서는 시스템 글꼴로 표시될 수 있으며, `.docx` 변환 도구가 아직 로드되지 않았다면 온라인 연결이 필요합니다. 텍스트·마크다운·자막 파일과 직접 입력한 대본은 오프라인에서 처리합니다. 자체 서버와 로그인은 없으며, 파일 처리는 브라우저에서 수행합니다.

## 개인정보와 집계

방문 규모와 연습 기능의 이용 흐름을 파악하기 위해 GoatCounter만 사용합니다. 쿠키와 브라우저에 저장하는 추적 ID는 사용하지 않습니다. 대본과 설정은 계속 사용자 브라우저에만 저장합니다.

- 수집 항목: 페이지 방문, 대본 열기(`script-open`), 재생 시작(`play-start`), 마지막 문장 재생 완료(`play-complete`), 발음 사전 다운로드 확인·재시도(`dictionary-confirm`)와 취소(`dictionary-cancel`), 공유 링크 복사 성공(`share-copy`). 대본 관련 이벤트에는 라이브러리 대본 ID 또는 `custom`만 포함합니다.
- 같은 대본의 재생 시작은 페이지를 연 동안 한 번만 전송합니다. 직접 넣은 대본은 내용별로 브라우저 메모리에서만 구분하며, 구분에 쓰는 내용이나 식별값을 보내지 않습니다. 마지막 문장까지 이동한 뒤 재생을 마친 경우에도 완료로 집계하므로 모든 문장을 읽었다는 의미는 아닙니다.
- 수집하지 않는 항목: 대본 본문·제목·사용자가 입력한 텍스트·파일명·파일 내용·검색어·설정값·URL 쿼리와 해시·유입 주소. 이벤트 제목은 고정 문구이며 화면 내용을 자동 수집하지 않습니다.
- 기본 요청에는 화면 너비와 자동화 브라우저 여부가 포함됩니다. 외부 서비스는 통신 과정에서 IP 주소와 브라우저 헤더를 받으며, GoatCounter는 이를 국가·브라우저·운영체제 등의 통계와 최대 8시간의 메모리상 방문 구분에 사용합니다. IP 주소 자체는 저장하지 않는다고 [개인정보 처리방침](https://www.goatcounter.com/help/privacy)에 명시합니다.
- `localhost`와 `127.0.0.1`에서는 집계 스크립트도 불러오지 않습니다. 스크립트 차단·로드 실패·오프라인 상태에서도 연습은 동작합니다. 로드 전 이벤트는 메모리에 최대 100개만 대기하며, 로드 실패 시 버립니다. 집계 데이터는 브라우저 저장소에 보관하거나 다음 방문에 재전송하지 않습니다.

설치는 [GoatCounter 시작 문서](https://www.goatcounter.com/help/start), 이벤트는 [이벤트 전송 문서](https://www.goatcounter.com/help/events)를 따릅니다. 비동기 로드 후 수동으로 전송하며, 기본 스크립트에 포함된 URL 쿼리(`q`)와 유입 주소를 전송 직전에 제거합니다. 외부 `count.js`와 집계 요청은 서비스 워커 캐시에 넣지 않습니다.
